# SaMu Sarcopenia Multi-Omics Pipeline

Jie Yuan
Gerber Lab
7/29/2026

This document describes the full multi-omics analysis pipeline built for the
SaMu sarcopenia cohort study: shotgun metagenomics (taxonomic + functional
profiling), NMR metabolomics, quorum-sensing-molecule profiling, proteomics
(DIA mass spec, GC-MS, LC-MS), and the shared machine-learning layer that
predicts sarcopenia status from each assay. It is organized as one document
per assay/component, each following the same shape: overview, upstream
processing, downstream statistics, outputs, and open questions/caveats
surfaced during development.

## 0. Project Architecture

The pipeline is organized as a set of sibling repositories, each owning one
stage or one assay:

| Repository | Role |
|---|---|
| `process_fastqs` | Bash/SLURM preprocessing: raw tar extraction through MetaPhlAn/HUMAnN profiling, run on `erishpc`. |
| `metagenomics_R` | Downstream R analysis of MetaPhlAn taxonomic profiles: filtering, diversity, DESeq2 differential abundance. |
| `humann_R` | Downstream R analysis of HUMAnN functional (pathway) profiles: filtering, MaAsLin3 modeling, ontology annotation. |
| `other_omics_R` | NMR metabolomics, quorum-sensing molecules, and DEP2-based proteomics/GC-MS/LC-MS differential abundance, plus shared plotting scripts. |
| `metagenomics_py` | Shared nested-cross-validation ML engine (`ml_engine.py`) with one loader per assay, predicting binary sarcopenia status. |

All study-specific values (paths, thresholds, database locations, covariate
lists) are centralized in a `config.R` / `config.sh` / `config.py` per
repository, so the numbered pipeline scripts themselves are not expected to
change between cohorts or re-runs. A recurring convention across the R
repositories is a shared `load_samu_metadata()` / `recode_samu_covariates()`
helper (`metadata_utils.R`) that standardizes covariate recoding (sex,
smoking, alcohol, binarized sarcopenia status) so it cannot drift between
assay-specific scripts.

Shared covariates used across nearly every downstream model:
`sarc_status_bin` (grouping factor; levels `NoSarc`, `Sarc`), `age_def`,
`sex`, `smke`, `alco`, `nutr_score`, `bmi`, and — for metagenomics/HUMAnN
specifically — `read_depth` as a technical covariate.

## 1. Metagenomics: Taxonomic Profiling

### 1.1 Overview
Shotgun metagenomic reads are taken from raw sequencer tar archives through
to per-sample MetaPhlAn taxonomic profiles and a downstream R pipeline that
produces diversity metrics and DESeq2 differential-abundance results. This
taxonomic layer is a sibling to the HUMAnN functional-profiling layer
(Section 2) — both consume the same host-removed, QC'd reads, and
`humann_R` explicitly reuses `metagenomics_R`'s recoded metadata
(`meta_df.rds`) rather than re-deriving it.

### 1.2 Preprocessing (`process_fastqs`, bash/SLURM on erishpc)
Runs in numbered stages, each with a serial ("plain-loop") script and, where
the original workflow needed one, a SLURM equivalent. All paths, database
locations, resource requests, and environment names live in `config.sh`.

| Stage | Script(s) | Purpose |
|---|---|---|
| 0 | `0_collect_tar_fastqs.sh` / `0_submit_extract_jobs.sh` | Extract `fastq.gz` from raw tar archives |
| 1 | `1_combine_L001_L002.sh` (+ `_multiple_replicates` variant) | Concatenate L001/L002 lanes per sample, optionally pooling replicate directories |
| 2 | `2_qc.sh` / `2_qc_array.slurm` + `make_qc_list.sh` | fastp trimming + fastqc + multiqc |
| 3 | `3_remove_host_reads.sh` / `3_remove_host_reads_job_submit.sh` | bowtie2 host alignment; unmapped pairs retained |
| 4 | `4_kraken.sh` | Kraken2 + Bracken classification |
| 5 | `5_metaphlan.sh` / `5_submit_metaphlan_jobs.sh` | Standalone MetaPhlAn profiling (superseded for HUMAnN purposes by internally-invoked MetaPhlAn — see Section 2.2) |

Design notes:
- **Idempotent stages.** Stages 2–5 skip a sample whose expected output
  already exists, so re-running after a partial failure only processes what's
  missing.
- **`SUBFOLD` consistency.** Stages 3 and 5 read/write `<dir>/$SUBFOLD`; keep
  it consistent across a run or set it to `""` if not using batch
  subdirectories.
- **Static `#SBATCH` directives.** SLURM cannot read shell variables in
  `#SBATCH` lines, so resource values in `2_qc_array.slurm` and
  `3_remove_host_reads_job.sh` are hardcoded and must be kept in sync with
  `config.sh`'s `SLURM_*` defaults by hand.
- **Disk cleanup.** Stages 3–5 remove large intermediates (SAM/BAM,
  decompressed/combined fastq) after each sample.
- **Sample naming.** Base names are derived by stripping known suffixes
  (`_R1_combined.fastq.gz`, `_R1_combined_fastp.fastq.gz`,
  `_host_removed_R1.fastq.gz`); no hand-maintained sample list is required
  except the SLURM array size for stage 2 (generated by `make_qc_list.sh`).

Tool requirements: `tar`, `fastp`, `fastqc`, `multiqc`, `bowtie2`,
`samtools`, `kraken2`, `bracken`, `metaphlan`, plus a Kraken2/Bracken
database, a bowtie2 host index, and a MetaPhlAn bowtie2 database.

### 1.3 Downstream Analysis (`metagenomics_R`)
Takes MetaPhlAn per-sample `*_profile.txt` files, joins to sample metadata,
filters, and produces diversity/differential-abundance results.

| Script | Role |
|---|---|
| `config.R` | Paths, thresholds, `FILE_ID_BLOCKS` mapping, DESeq2 design. |
| `utils.R` | `build_file_id`, `recode_metadata`, `read_metaphlan`, `tag_filename`, `renormalize_relab`, shared palette. |
| `01_load_and_filter.R` | Metadata recode + File_ID link, load profiles, species-level collapse, abundance/prevalence filter, elbow-plot diagnostic. |
| `02_diversity.R` | Family/genus stacked barplots (Bray-Curtis clustered); alpha diversity (normalized Shannon) + Wilcoxon; beta diversity (PCoA + PERMANOVA). |
| `03_differential_abundance.R` | DESeq2 on species-level counts with covariate adjustment + apeglm shrinkage; faceted dotplot of significant species. |
| `04_ordinal_lasso.R` | Proportional-odds ordinal regression (`ordinalNet`) as an alternative to the binary DESeq2 contrast. |

State passes between scripts via `meta_filtered.rds` and `meta_df.rds`
written into `OUTPUT_DIR`, so `02`/`03` can be re-run independently once `01`
has completed.

Key configuration knobs:
- **`FILE_ID_BLOCKS`** — a per-sequencing-block column-to-regex mapping used
  to build the `File_ID` that links metadata rows to profile files (each
  block stores its file reference differently); blocks apply in order, with
  a later non-empty match overriding an earlier one for the same row.
- **`ABUND_THRESHOLD` / `MIN_SAMPLES`** — abundance/prevalence filter,
  diagnosed via `01`'s elbow plot.
- **`DESEQ_DESIGN` / `DESEQ_COEF` / `SCALE_COVARIATES`** — DESeq2 design
  formula (grouping variable last), the `resultsNames(dds)` coefficient
  passed to `lfcShrink`, and which continuous covariates get z-scored into
  `<name>_scaled` columns. The complete-case filter derives its columns from
  `all.vars(DESEQ_DESIGN)`, so changing the formula automatically changes
  which samples are retained.
- **`GROUP_VAR` / `GROUP_LEVELS`** — the binary contrast (`sarc_status_bin`:
  `NoSarc`/`Sarc`) used across all three scripts.

Software: `dplyr`, `tidyr`, `purrr`, `readr`, `ggplot2`, `stringr`,
`forcats`, `viridis`, `vegan`, `phyloseq`, `DESeq2` (Bioconductor),
`tidytext`, `rstatix`, `apeglm` (Bioconductor).

### 1.4 Established Configuration on erishpc
A working HUMAnN 3.9 + MetaPhlAn 3.1.0 pipeline was established using the
pre-SGB `v201901_v31` ChocoPhlAn database and a dedicated `metaphlan31_env`
environment (superseded by the internally-invoked MetaPhlAn 4.1.1
configuration described in Section 2.2, which resolved the species-matching
issue that motivated re-evaluating the database version). Key learnings
included version-compatibility constraints between HUMAnN/MetaPhlAn/ChocoPhlAn
releases and converting ad hoc job submission into reliable SLURM array jobs
(`5b_submit_metaphlan_v31_jobs.sh`, `6_submit_humann_jobs.sh`). Merged HUMAnN
output lives at
`/data/bwh-comppath-full/gerberlab/jy1008/SaMu/metagenomics/humann_out/all_merged_fastqs_merged`.

## 2. HUMAnN Functional Profiling

### 2.1 Overview
Functional metagenomic profiling of the SaMu cohort: taxonomic profiling
(MetaPhlAn, invoked internally), functional profiling (HUMAnN), table
merging/normalization, and downstream R statistics (feature filtering,
MaAsLin3 differential abundance/prevalence testing, pathway ontology
annotation, redundancy checking). Two layers:
- **Bash/SLURM (`samu-metagenomics`)** — MetaPhlAn + HUMAnN per sample on
  erishpc, followed by table merging and normalization.
- **R (`humann_R`)** — sample-metadata alignment, feature filtering, MaAsLin3
  modeling, pathway ontology annotation, result visualization.

### 2.2 Taxonomic Input to HUMAnN
HUMAnN requires a MetaPhlAn taxonomic profile (via `--taxonomic-profile`) to
restrict its nucleotide-level search to a sample-specific pangenome database
rather than searching the full ChocoPhlAn database per read.

**Database compatibility.** HUMAnN 3.x's ChocoPhlAn nucleotide pangenome
database (`v201901_v31`) predates MetaPhlAn 4's Species Genome Bin (SGB)
taxonomy: `v201901_v31` uses named genus/species pangenomes
(`g__Veillonella.s__Veillonella_atypica`), while SGB-based MetaPhlAn 4
databases (`vJun23_CHOCOPhlAnSGB_202403`) can additionally report
SGB-numbered clades (`t__SGB6936`) or candidate genome bins (`c__CFGB1764`)
with no ChocoPhlAn `v201901_v31` equivalent. Feeding HUMAnN a profile
generated against a mismatched/auto-installed MetaPhlAn database matched only
~9% of predicted community composition to ChocoPhlAn pangenomes. HUMAnN 3.x
also hard-rejects any ChocoPhlAn version other than `v201901_v31` if supplied
directly. A HUMAnN 4.0 (alpha) release with native SGB-based ChocoPhlAn
(`chocophlan.v4_alpha` + `vOct22`) was evaluated and **not adopted**: its
UniRef90 build is EC-annotated-only (no full build for that HUMAnN version),
and the release has no fixed timeline.

**Current configuration.** HUMAnN 3.9 with MetaPhlAn 4.1.1 and
`vJun23_CHOCOPhlAnSGB_202403`, MetaPhlAn invoked internally via
`--metaphlan-options` rather than as a separate upstream step. The ~9%
match-rate issue traced in part to MetaPhlAn auto-installing a
newer/mismatched database; explicitly pointing HUMAnN's internal MetaPhlAn
call at the correct pre-installed `vJun23_202403` database resolved the
compatibility error, and species-level matching has been high since.

```
humann --input '$comb_file' --output '$sample_out_dir' \
       --nucleotide-database '$HUMANN_CHOCOPHLAN_DB' \
       --protein-database '$HUMANN_UNIREF_DB' \
       --metaphlan-options '--bowtie2db /data/bwh-comppath-seq/databases/bowtie2 --index mpa_vJun23_CHOCOPhlAnSGB_202403' \
       --threads $CPUS;
```

### 2.3 Functional Profiling (HUMAnN)
Run per sample against standard HUMAnN 3.x databases: nucleotide (ChocoPhlAn
`v201901_v31`, full) and protein (UniRef90, full diamond build
`uniref90_201901b_full.dmnd`). Two-stage search: (1) nucleotide alignment
(bowtie2) against ChocoPhlAn, (2) translated search (DIAMOND) against
UniRef90 for stage-1-unmapped reads. Gene families (UniRef90 IDs, optionally
species-stratified) are aggregated into MetaCyc pathway abundance/coverage.

```
humann --input <combined_R1R2.fastq.gz> --output <sample_out_dir> \
  --nucleotide-database <chocophlan_v201901_v31_path> \
  --protein-database <uniref_path> \
  --metaphlan-options "-x vJun23_CHOCOPhlAnSGB_202403 --bowtie2db <path>" \
  --threads <N> --remove-temp-output
```
`--remove-temp-output` is used because HUMAnN's intermediate directory
(custom pangenome index, raw alignments, unaligned-read carryforwards,
internal MetaPhlAn output) can reach ~100 GB/sample and is not needed once
`genefamilies`/`pathabundance`/`pathcoverage` outputs are written.

### 2.4 Table Merging and Normalization
Per-sample outputs (`genefamilies.tsv`, `pathabundance.tsv`,
`pathcoverage.tsv`) are merged with `humann_join_tables`, then renormalized
from raw RPK to relative abundance with `humann_renorm_table` (RPK is not
directly comparable across samples of differing sequencing depth).

`humann_join_tables` requires all input files as regular files directly
inside one flat directory — it does not recurse into per-sample
subdirectories and silently reports "Zero gene tables were found to join"
(exit 0) on a nested/symlinked structure. The merge script stages hardlinks
(not symlinks, also silently skipped) into a flat directory first, and
explicitly checks for non-empty output after each call rather than trusting
the exit code. Downstream outputs: `joined_pathabundance_relab.tsv`,
`joined_genefamilies_relab.tsv`.

### 2.5 Downstream Statistical Analysis (`humann_R`)
Structured as a sibling to `metagenomics_R`, reusing its already-recoded,
complete-case-filtered subject metadata (`meta_df.rds`) rather than
re-deriving `File_ID` construction or covariate recoding.

**Sample identifier matching.** `humann_join_tables` names each column after
the input filename with the file-type suffix stripped (e.g.
`SaMu9_host_removed_R1R2_combined_humann_pathabundance.tsv` →
`SaMu9_host_removed_R1R2_combined_humann`), which does not match the
metadata `File_ID` (`SaMu9`). Column names are resolved via
`extract_sample_id()`: a known-suffix strip (`STRIP_SUFFIX_REGEX`) followed
by ordered block-specific regexes (`FILE_ID_REGEXES`), mirroring
`metagenomics_R`'s `FILE_ID_BLOCKS` logic. `diagnose_sample_matching()`
prints match counts and example unmatched IDs from both sides before any
alignment is trusted.

**Feature filtering.** Unstratified (community-total) rows only
(species-stratified rows containing `|` are excluded). Three filters applied
jointly, each over nonzero sample values:

| Filter | Threshold | Rationale |
|---|---|---|
| Mean relative abundance | ≥ 1e-5 | Lowered from the MaAsLin2 tutorial default (1e-4) per data-driven inspection of this cohort's abundance distribution. |
| Prevalence | ≥ 0.10 (fraction nonzero) | MaAsLin2 tutorial default, retained as-is. |
| Coefficient of variation (sd/mean) | Top 50% by CV percentile (data-derived) | Removes near-universal, low-variance core pathways; follows prior lab convention (Jen Dawkins). |

`MIN_CV` is derived from the data each run (top `MIN_CV_PERCENTILE` of the
observed CV distribution), not a fixed raw value. Diagnostic elbow plots
(features retained vs. threshold, swept independently for abundance and CV)
and abundance/CV histograms are written before filtering. Note: MaAsLin3's
own tutorial states prevalence/abundance filtering is not strictly necessary
(its model separates abundance and prevalence sub-models), but can still
increase power — the CV filter is applied for that reason, on top of (not
instead of) MaAsLin3's native handling.

**MaAsLin3 model.**

| Parameter | Value |
|---|---|
| Fixed effects | `sarc_status_bin`, `read_depth`, `age_def`, `sex`, `smke`, `alco`, `nutr_score`, `bmi` |
| Random effects | none |
| Normalization | TSS (default) |
| Transform | LOG (default) |
| `max_significance` | 0.1 |

`read_depth` (post-QC, post-host-removal count from per-sample fastp JSON) is
included on MaAsLin3's own recommendation: since the model tests prevalence
associations explicitly, deeper sequencing can otherwise present as a
spurious prevalence association with any depth-correlated covariate. It is
treated strictly as a technical covariate, never reported as a biological
finding.

MaAsLin3's `qval_joint` is FDR-corrected across every fixed effect
simultaneously — unnecessarily conservative when only `sarc_status_bin` is
of direct interest. `plot_maaslin_results.py` isolates that term from
`all_results.tsv` and re-applies BH correction to it alone, per MaAsLin3's
documented guidance.

**Pathway ontology and redundancy checks.** Surviving pathways are annotated
with MetaCyc ontology ancestry via a manually-built BioCyc SmartTable export
(chained "Ontology – direct parents" columns, truncated at the "Pathways"
root class). Note: once a pathway has more than one direct parent, the
chained export loses exact parent/grandparent pairing per branch — each
column is a breadth layer, not a resolved tree; sufficient for a hierarchy
report, not exact-edge distances. Two independent redundancy checks:
- **Structural** — pathways whose direct parent includes "Super-Pathways" are
  flagged as composite candidates; confirmed via an optional "Sub-Pathways"
  cross-check.
- **Statistical** — pairwise Spearman correlation (not Pearson, for
  compositional/skewed data) across the filtered abundance matrix; pairs
  with |correlation| ≥ 0.9 flagged regardless of MetaCyc structure. The
  correlation-distribution histogram is inspected before trusting this
  threshold.

**Pathway → GO terms.** Gene families (UniRef90) map directly to GO via
`humann_regroup_table` (`--groups uniref90_go` or curated
`uniref90_infogo1000`). MetaCyc pathways have no native GO mapping; the
approach used submits pathway IDs to MetaCyc.org as a SmartTable and walks
the pathway's native MetaCyc ontology tree (same mechanism as the redundancy
analysis) — a defensible MetaCyc-native categorization, not a formal GO
mapping.

**Pathways over gene families.** Pathway-level testing
(`FEATURE_TABLE = "pathabundance"`) is the primary unit for interpretability:
gene families number in the hundreds of thousands per merged table (131,960
rows in a single-sample `genefamilies.tsv`) with no inherent biological
label, versus a few thousand human-readable MetaCyc pathways. Gene-family
testing is supported by switching `FEATURE_TABLE` but has not been the
reporting focus, in part because no pathway-level features reached nominal
significance, lowering the priority of a higher-multiplicity follow-up.

## 3. NMR Metabolomics

### 3.1 Overview
Metabolite concentration analysis from targeted NMR (`01a_nmr.R` in
`other_omics_R`). Joins the NMR assay table to metadata recoded independently
from the raw metadata CSV (not the metagenomics output), since NMR samples
can fall outside the metagenomics cohort. Runs independently of the
quorum-sensing analysis (Section 4) — neither script requires the other's
input. (A separate, unrelated pipeline, `dFBA/NMR`, consumes NMR trajectory
data for constraint-based metabolic flux modeling — see note at end of this
section — and is not part of this differential-analysis layer.)

### 3.2 Data Handling
- Metadata loaded via `load_samu_metadata()`, filtered to `Full.SaMu == 1`,
  covariates recoded (smoking/alcohol binarization, sex, `sarc_status_bin`).
- NMR concentrations read from
  `20251027_SaMu_NMR_ureum_creat_v10.csv`, metabolite columns starting at a
  configured column index.
- A below-detection-limit placeholder value (`UNK_E_1`) is replaced with `0`
  in NMR columns before numeric coercion.
- A left join keeps every retained metadata sample and attaches NMR values
  where present (metadata is the "spine"; NMR is not required for every
  sample).

### 3.3 Transform and Normalization
NMR concentrations are **not compositional** data, so the pipeline
deliberately uses log10 concentrations directly (with a small epsilon,
1e-6) rather than converting to relative abundances the way metagenomics/
HUMAnN data are. The resulting matrix is z-scored (`scale()`) per feature.
Because Bray-Curtis is a compositional-data distance, its use for NMR beta
diversity is explicitly flagged as a rough approximation, to be interpreted
with caution.

### 3.4 Analyses Produced
- **Clustered heatmap** of scaled log concentrations (`ward.D2`, rows split
  by group with within-group clustering, columns clustered).
- **Beta diversity** — Bray-Curtis distance, PCoA, colored by group/sex and
  by total concentration ("read depth" analogue for a non-sequencing assay).
- **PCA** on the scaled log matrix, colored by group, age, and total
  concentration.
- **Per-metabolite Wilcoxon tests** (`sarc_status_bin` contrast) with BH
  correction, rendered as boxplots with jittered points and p/q-value
  annotations, ordered by raw p-value.

### 3.5 Outputs
`samu_nmr_FullSaMu.csv` (merged raw table), `samu_nmr_logrel_scaled.csv`
(scaled log matrix, group-ordered), `samu_nmr_logrel_scaled.pdf` (heatmap),
PCoA/PCA PDFs, `nmr_wilcoxon_boxplot.pdf`.

### 3.6 Visualization (`plot_nmr_quorum_results.py`)
A shared Python script (used by both NMR and quorum sensing, Section 4)
renders a summary figure directly from the R pipeline's raw + scaled CSVs —
no extra export step required:
```
python plot_nmr_quorum_results.py \
    --raw samu_nmr_FullSaMu.csv \
    --scaled samu_nmr_logrel_scaled.csv \
    --out nmr_top_features --top-n 10
```

## 4. Quorum-Sensing-Molecule Profiling

### 4.1 Overview
Analysis of quorum-sensing peptide (QSP) quantification data (`01b_quorum.R`
in `other_omics_R`), structured in parallel to the NMR script (Section 3)
and sharing its `matrix_utils.R` helpers (`build_matrix`,
`group_annotation`) so the two scripts' clustering/annotation logic cannot
drift apart. Runs independently of NMR data.

### 4.2 Data Handling and Grouping Levels
- Quorum assay table (`20251030_SaMu_QSP_data_v3.csv`) columns matched by
  regex (`_Quant\.Prob$`); a below-detection placeholder is zeroed before
  numeric coercion, same convention as NMR.
- A separate QSP → Species / Microbial_target grouping reference
  (`QSP_overview_PN1_long.csv`) is trimmed of stray whitespace (the source
  table has inconsistent trailing spaces, e.g. `"Streptococcus mitis "` vs.
  `"Streptococcus mitis"`, which would otherwise split one species into two
  groups) and blank grouping entries become `NA`.
- `aggregate_quorum_cols()` collapses QSP-level quant\*prob columns to a
  requested grouping level (`QSP` pass-through, `Species`, or
  `Microbial_target`) by summing within group. A sample is genuinely missing
  at a grouping level only if *every* QSP feeding into it is `NA`
  (untested); if at least one QSP was measured, untested peers contribute 0
  to the sum rather than blanking out an otherwise-observed group.
- The analysis loop runs once per grouping level (QSP, Species,
  Microbial_target), each producing its own CSV/heatmap/PCA/boxplot set.

### 4.3 Transform, Missingness, and Clustering
Like NMR, raw (grouped) quant\*prob values are log10-transformed directly
(no compositional normalization) and z-scored. Genuine missingness (a QSP
never tested for a sample) is preserved as real `NA` rather than zero-filled
— a change from an earlier version of the script that zero-filled it,
conflating "never tested" with "measured, below detection." This has
downstream consequences that the script handles explicitly:
- `pheatmap`'s own column clustering computes a plain `dist()`, which errors
  (`NA/NaN/Inf in foreign function call`) once most column pairs share an NA
  row. Column-clustering distances are computed on a zero-filled *copy* of
  the matrix (`clustering_distance_cols`); the displayed heatmap cells still
  come from the real (NA-preserving) matrix, with NA rendered as light gray.
- `prcomp()` requires a complete matrix. Dropping any column with even one
  NA (the earlier convention) now drops most/all columns and fails outright
  (`"a dimension is zero"`). The PCA input is zero-filled for computation
  only, on the already-z-scored matrix (0 = "at that feature's mean" — the
  least-assumption placeholder); heavily-missing samples/features are pulled
  somewhat toward the PCA origin as a result.
- Per-feature Wilcoxon tests can now hit features with too few (or zero)
  non-NA observations in one group after NA removal. `safe_wilcox_p()` wraps
  `wilcox.test()` so one under-powered feature logs a skip message and
  returns `NA` rather than aborting the loop over all features; skipped
  features still count toward `n` in the BH correction (`p.adjust(...,
  n = length(p_value))`), since they were still part of the family of tests
  attempted.

### 4.4 Analyses Produced (per grouping level)
Clustered heatmap (annotation colors: `#ff9289` NoSarc / `#00dae0` Sarc, NA
cells light gray), PCoA/PCA colored by group / age / total quant\*prob
signal ("total_signal", the quorum analogue of NMR's read-depth), and
per-feature Wilcoxon boxplots with BH-adjusted p-values.

### 4.5 Outputs
Per level (`qsp`, `species`, `microbial_target`):
`samu_quorum_raw_<level>.csv`, `samu_quorum_log_scaled_<level>.csv`,
`samu_quorum_log_scaled_<level>.pdf`, PCA PDFs,
`quorum_wilcoxon_boxplot_<level>.pdf`. Raw exports match the NMR raw-table
shape (`record_id` + group + one column per feature) specifically so
`plot_nmr_quorum_results.py` can be reused unmodified across all three
levels.

### 4.6 Visualization
```
python plot_nmr_quorum_results.py \
    --raw samu_quorum_raw_qsp.csv --scaled samu_quorum_log_scaled_qsp.csv \
    --pseudocount 1e-6 --value-label "Quant*Prob" --feature-label "QSP" \
    --out quorum_qsp_fig --stats-out quorum_qsp_stats.csv
```
(analogous invocations for the `species` and `microbial_target` levels)

## 5. Proteomics (DIA Mass Spectrometry)

### 5.1 Overview
Proteomics differential-abundance testing shares one script,
`02_proteomics_dep2.R`, with the GC-MS and LC-MS assays (Sections 6–7),
unified via a `loader` switch in `config.R`'s `PROTEOMICS` block. Proteomics
specifically uses `loader = "massspec"`, reading per-sample long-format DIA
output rather than the batch-wide peak tables used by GC-MS/LC-MS.
Downstream of the loader, all four assays (proteomics, GC-MS, LC-MS
positive/negative) share one path: `make_se` → `filter_se` → `normalize_vsn`
→ `impute` → `test_diff` → heatmap (DEP2, the SummarizedExperiment-based
package originally built for label-free proteomics).

### 5.2 Massspec Loader and QC
Per-sample long CSVs (`Protein.Group`, `Gene.names`, `Global.Q.Value`,
`RawCount`, `contaminant`, etc.) are read and combined. Sample labels are
recovered by stripping configured prefix/suffix strings
(`sample_name_strip`) from each filename.

**QC.** A contaminant/Q-value bin barplot is written for inspection, then
rows are filtered to non-contaminant, `Global.Q.Value < qvalue_cutoff`
(0.01). The cleaned long table is pivoted wide on `SampleID`/`RawCount`,
with `ID` built as `Protein.Group;Gene.names`.

Note: `DEP2` loads `S4Vectors`, which defines its own `rename()` generic
(for `DataFrame`/`GRanges`, with a different argument convention than
dplyr's) that masks `dplyr::rename()` once DEP2 is attached — and likewise
`reduce()` is masked by `S4Vectors`/`IRanges`'s own generic for `Ranges`
objects. Both calls are explicitly namespaced (`dplyr::rename`,
`purrr::reduce`) throughout the script to avoid silently picking up the
wrong generic.

### 5.3 Internal-Standard Normalization
Not typically applicable to massspec (DIA) runs — `internal_standard = NA`
skips this step for proteomics, in contrast to the GC-MS configuration
(Section 6) which uses it. When enabled for a `wide`-loader assay, the same
`normalize_to_internal_standard()` function used for GC-MS (Section 6.3) is
shared verbatim across all `PROTEOMICS` variants.

### 5.4 DEP2 Pipeline (shared with GC-MS/LC-MS)
1. **`make_se()`** builds the SummarizedExperiment (log2-transforms the
   assay internally); sample metadata (`condition`, from `sarc_status_bin`;
   `replicate`, parsed from the sample label) supplied as `expdesign`.
2. **`filter_se(thr, fraction)`** removes features with too much
   missingness. Massspec defaults: `filter_thr = 50`, `filter_fraction =
   0.25` — a lenient valid-value threshold, not a missing-value threshold
   (`fraction` is the fraction of *valid* values required, easy to misread
   in the opposite direction).
3. **`normalize_vsn()`** — variance-stabilizing normalization on top of the
   filtered matrix.
4. **`impute(fun = "MinDet")`** — minimal detection limit imputation for
   values missing below the instrument's detection threshold.
5. **`test_diff(type = "manual", test = "Sarc_vs_NoSarc", fdr.type = "BH")`**
   + `add_rejections()`. Reported: effect size (`diff`), CI (`CI.L`/`CI.R`),
   raw/BH-adjusted p-values, DEP2 t-statistic.

Massspec-specific: `heatmap_top_n = 50` (vs. `Inf` for GC-MS/LC-MS, which
show all tested features ordered by p-value).

### 5.5 Outputs
`proteomics_dep2_results.csv`, `proteomics_dep2_vsn_matrix.csv`,
`proteomics_dep2_vsn_imputed_metadata.csv`, volcano PDF (DEP2's own
`plot_volcano()`), top-N clustered heatmap PDF (pre-imputation, so genuine
missingness is visible as gray cells). See Section 6.5/6.6 for the shared
export/visualization caveats (label mismatch fix, double-log-transform fix)
that apply identically here.

### 5.6 Visualization
```
python plot_dep2_results.py \
    --input proteomics_dep2_results.csv \
    --contrast Sarc_vs_NoSarc --experiment-name proteomics \
    --abundance-table proteomics_dep2_vsn_matrix.csv \
    --sample-metadata proteomics_dep2_vsn_imputed_metadata.csv \
    --output proteomics_dep2_volcano_top_features
```

## 6. GC-MS Metabolomics

### 6.1 Overview
GC-MS peak-table differential-abundance testing using the same
`02_proteomics_dep2.R` / DEP2 pipeline as Section 5, with `loader = "wide"`
and `experiment_name = "GC_MS"`. Operates on GC-MS peak intensity tables
exported per acquisition batch (one CSV per batch, samples as rows, named
metabolites as columns):
`GCMS_processed_blocks1_5_6_7_SaMu_2_28and165_296.csv`,
`GCMS_processed_blocks2,3,4_SaMu_29_164.csv`,
`GCMS_processed_blocks8,9_SaMu_298_371.csv`.

A standalone Python script, `plot_dep2_results.py`, renders a three-panel
summary figure directly from the R pipeline's output CSVs.

### 6.2 Input Loading (`wide` loader)
Each batch CSV (first column `Sample`, remaining columns named metabolites)
is transposed and full-outer-joined across batches on feature name — a
metabolite reported in one batch but absent from another becomes `NA` for
that batch's samples rather than being dropped. Feature names follow
`[ID] compound name [RT]`, e.g.
`"[10394] 3-(4-hydroxyphenyl)propionic acid [15.979]"`.
Sample covariates are joined on sample label (`SaMuNNN`) via
`load_samu_metadata()`.

### 6.3 Internal-Standard Normalization
**Rationale.** GC-MS intensities carry sample-to-sample technical variation
(injection volume, ionization efficiency). Normalizing every feature's
intensity to that sample's internal-standard intensity corrects for this,
assuming the standard tracks technical variation but not the biology of
interest. Standard used: `4-Nitrobenzoic acid, TMS derivative` (already
present as a feature in the raw table).

**Method.** For sample *i*, feature *j*:
`normalized_ij = (raw_ij + pseudocount) / standard_i`. The standard's own
intensity is matched by *substring* (not exact equality) against the
feature ID column, since the bracketed `[ID] ... [RT]` wrapper means a
short, human-typed standard name won't match the stored feature string
exactly; the match must be unique, or the function errors listing the
candidates rather than silently normalizing to the wrong feature.

Only genuinely-observed (nonzero, non-NA) cells are normalized; cells
missing in the raw data stay `NA` rather than being divided through. This
matters because DEP2's `make_se()` log2-transforms the assay at
construction — a literal `0` becomes `log2(0) = -Inf`, not `NA`, and unlike
`NA`, `-Inf` is not excluded by `scale()` when the heatmap z-scores each
feature: a single `-Inf` poisons the mean/SD (and therefore the z-score) for
every sample in that feature's row.

**Two normalization bugs caught during implementation** (both around this
missing-value handling): (1) the pseudocount was first added to *every*
cell including missing ones, converting all missing 0s to small positive
numbers — `DEP2::impute()` then errored with `"No missing values in
'se_filt'"` because nothing was left to impute; (2) missing cells were then
forced back to literal `0` after normalization, which (via the log2/`-Inf`
mechanism above) poisoned the heatmap's z-scoring, leaving it almost
entirely gray. The current implementation preserves missing cells as real
`NA` throughout, resolving both.

The standard's own feature row is dropped after normalization so it is not
itself tested or clustered downstream.

| Parameter | Value (GC-MS) | Notes |
|---|---|---|
| `internal_standard` | `"4-Nitrobenzoic acid, TMS derivative"` | `NA` disables normalization (used for LC-MS configs without a standard). |
| `internal_standard_pseudocount` | 1 | Added to the numerator only, before dividing. |
| `internal_standard_log` | `FALSE` | Left off deliberately — `normalize_vsn()` downstream already log-transforms; logging here too would double-log. |

### 6.4 DEP2 Pipeline
Same five steps as Section 5.4. GC-MS-specific parameters:
`filter_thr = 0`, `filter_fraction = 0.25` (a lenient valid-value threshold,
keeping any feature with ≥25% valid values in at least one condition),
`impute_fun = "MinDet"`, `de_test = "Sarc_vs_NoSarc"`,
`heatmap_top_n = Inf` (show all tested features, ordered by p-value).

### 6.5 Outputs
- `GC_MS_dep2_results.csv` — one row per surviving feature: `name`, `ID`,
  `imputed`, `num_NAs`, per-contrast `CI.L`/`CI.R`/`diff`/`p.adj`/`p.val`/
  `t.stastic`/`significant`.
- `GC_MS_dep2_vsn_imputed_matrix.csv` — sample × feature, VSN-normalized,
  fully imputed. Uses `colData(se_imp)$label` (the original `SaMuNNN` label)
  for the `Sample` column — **not** the assay's own column names. DEP2
  internally renames the assay's columns to a `condition_replicate` scheme
  (e.g. `"Sarc_243"`); an earlier export version used
  `rownames(t(assay(se_imp)))`, which reflected those renamed columns and
  caused a near-total sample-ID mismatch against the metadata CSV
  downstream. The fix pulls `colData(se_imp)$label` directly, guaranteed
  row-aligned with the assay's columns.
- `GC_MS_dep2_vsn_imputed_metadata.csv` — full covariate table (not just
  `colData(se_imp)`, which only carries DEP2's own internal columns and
  would drop every named covariate), row-matched via `label`.
- `GC_MS_dep2_volcano.pdf` (DEP2's `plot_volcano()`) and
  `GC_MS_dep2_heatmap.pdf` (top-DE-feature clustered heatmap, built from
  `assay(se_filt)` — pre-imputation, so genuine missingness stays visible as
  gray cells).

Note: `assay(se_filt)` is already on DEP2's internal log2 scale. The heatmap
code previously applied a second `log10()` on top of it, silently harmless
while raw intensities stayed well above 1, but broke once
internal-standard-normalized ratios could fall below 1 — `log2` of a
sub-1 ratio is negative, and `log10()` of a negative number is `NaN` in R.
This is what actually caused an earlier "almost all gray" heatmap symptom —
a separate, smaller issue than the missing-value bugs above, caught first.
Fix: the redundant `log10()` was removed entirely.

### 6.6 Visualization (`plot_dep2_results.py`)
Three panels, built directly from the R pipeline's output CSVs (no extra
export step): **A** volcano (`diff` vs. −log10 p-value, colored by imputed
status), **B** top-N bar chart by q-value with CI error bars, **C** optional
clustered per-sample heatmap of the same top-N features (row z-scored,
columns split/clustered by group). Design choices specific to this
DEP2-based script, relative to its MaAsLin3-output analog
(`plot_maaslin_results.py`):
- Colors by **imputed status** (DEP2 has no abundance/prevalence submodel
  split to color by).
- **Recomputes** BH q-values directly from the raw p-value column rather
  than trusting DEP2's own `p.adj`, since `--omit-features` changes the
  tested feature set and the correction must be over the set actually being
  reported.
- **No log-transform** in Panel C — the imputed matrix is already on DEP2's
  VSN-normalized (log2-like) scale; the MaAsLin3 analog's
  `log10(x + pseudocount)` on raw relative abundances would double-transform
  this data.

```
python plot_dep2_results.py \
    --input GC_MS_dep2_results.csv --contrast Sarc_vs_NoSarc \
    --experiment-name GC-MS \
    --abundance-table GC_MS_dep2_vsn_imputed_matrix.csv \
    --sample-metadata GC_MS_dep2_vsn_imputed_metadata.csv \
    --sample-id-col label --group-col sarc_status_bin \
    --output GC_MS_dep2_volcano_top_features
```
Produces `<output>.pdf`/`.png` (300 DPI) and `<output>_table.csv` (recomputed
q-values, for auditability).

### 6.8 Preliminary Results
With `filter_fraction = 0.25`, 48 features survived filtering and were
tested; 0 significant at q < 0.1. The sparsity of the combined GC-MS peak
table (not an overly strict filter) drives the low tested-feature count —
`02_proteomics_dep2.R` writes a filtering-threshold sweep diagnostic
(`dep2_se_filtering_thresholds.pdf`, features retained across a thr/fraction
grid) to judge the retained-count vs. missingness/reliability tradeoff. With
only 48 features tested and none significant, checking that sweep is worth
doing before concluding there is no signal — fewer tested features means
less multiple-testing burden, but also fewer chances for real signal among
features filtered out upstream to surface.

## 7. LC-MS Metabolomics

### 7.1 Overview
LC-MS (positive and negative ionization mode) is processed through the same
`02_proteomics_dep2.R` / DEP2 pipeline as GC-MS (Section 6), with
`loader = "wide"`, each mode as its own `PROTEOMICS` config variant
(`experiment_name = "LC_MS_neg"` / `"LC_MS_pos"`). Only one `PROTEOMICS`
block is active at a time in `config.R`; switching assays means commenting
out the active block and uncommenting the target one. LC-MS additionally has
a one-off feature-exploration step (`03_lc_feature_exploration.R`) not
present for GC-MS or proteomics, used to cluster highly-correlated,
co-eluting peaks before differential testing.

### 7.2 Configuration (LC-MS pos/neg)
Both modes share the GC-MS filtering defaults (`filter_thr = 0`,
`filter_fraction = 0.25`, sweep grids identical to GC-MS/massspec) and
`heatmap_top_n = Inf`. Unlike GC-MS, `internal_standard = NA` for both
modes as configured — no LC-MS internal standard is currently set, though
the same `normalize_to_internal_standard()` machinery (Section 6.3) would
apply unmodified if one is added later.

| Parameter | LC-MS neg | LC-MS pos |
|---|---|---|
| `parent_dir` | `.../proteomics/LC_MS_neg` | `.../proteomics/LC_MS_pos` |
| `experiment_name` | `LC_MS_neg` | `LC_MS_pos` |
| `internal_standard` | NA (unset) | NA (unset) |

### 7.3 Feature Exploration and Clustering (`03_lc_feature_exploration.R`)
An exploratory, one-off script (not a routine per-run pipeline step) applied
to a specific LC-MS positive-mode file set
(`LCMS_processed_blocks8,9,1PY2_SaMu_298_371and5PY2_25PY2_pos.csv`). Purpose:
LC-MS peak tables can contain many highly-correlated, co-eluting peaks that
represent the same underlying compound (in-source fragments, adducts,
isotopes); this step collapses them before they are treated as independent
features in differential testing.

1. **Feature-presence audit** across input files — counts features per file
   and how many files each feature appears in
   (`<experiment>_feature_file_presence.csv`).
2. **Combine to one feature × sample matrix**, sample-name underscores
   stripped to match metadata labels, missing values zero-filled, then
   filtered to peaks present (nonzero) in at least `peak_filter_threshold`
   (0.25) of samples.
3. **Peak-peak correlation network** — pairwise correlation
   (`cor(t(mat), use = "pairwise.complete.obs")`), rendered as a heatmap for
   inspection; an unweighted adjacency graph is built from pairs with
   correlation ≥ `corr_threshold` (0.8), and connected components
   (`igraph::components()`) define clusters. Clusters smaller than
   `min_cluster_size` (2) are dropped.
4. **Collapse each cluster** to a representative value (`mean` or `max`,
   configurable via `cluster_summary`), producing a clustered sample ×
   feature matrix in the same `Sample` + feature-column "wide" layout
   consumed by `02_proteomics_dep2.R` (`loader = "wide"`) — so differential
   testing is run through the shared DEP2 backbone (Section 6.4) rather than
   duplicated in this script.

| Parameter | Value |
|---|---|
| `peak_filter_threshold` | 0.25 |
| `corr_threshold` | 0.8 |
| `min_cluster_size` | 2 |
| `cluster_summary` | `"mean"` |

Output: `<experiment_name>_clustered_features.csv`, fed back into
`02_proteomics_dep2.R` with `loader = "wide"` for the actual DE test.

### 7.4 DEP2 Pipeline, Outputs, Visualization
Identical mechanics to GC-MS (Sections 6.4–6.6): `make_se` → `filter_se` →
`normalize_vsn` → `impute(MinDet)` → `test_diff(Sarc_vs_NoSarc)`, the same
`label`-based sample-ID export fix, and the same `plot_dep2_results.py`
three-panel visualization (imputed-status coloring, recomputed BH q-values,
no double log-transform).

## 8. Cross-Assay ML Prediction Pipeline (`metagenomics_py`)

### 8.1 Overview
Nested cross-validation models predicting binary sarcopenia status
(`sarc_status > 0`) from each omics assay plus clinical covariates. All four
assays (metagenomics, proteomics/mass-spec, NMR, LC/GC-MS) share one engine
— only data loading differs — so per-assay entry scripts are thin.

```
fcnn_wrapper.py        FC_NN (skorch/PyTorch) classifier + builder
ml_engine.py           Nested-CV engine: model defs, ColumnTransformer, ROC plot
feature_importance.py  Post-hoc extractors (lasso coef, Boruta RF, FC_NN IG, merge)
loaders.py             One loader per assay -> (X, y, feature_groups, binary_cols)
config.py              Per-assay paths + shared seeds/metric
run_metagenomics.py    Entry script: MetaPhlAn species
run_mass_spec.py       Entry script: DEP2 VSN proteomics
run_nmr.py             Entry script: NMR metabolites + taxa
run_lc_gc_ms.py        Entry script: LC/GC-MS features
```

### 8.2 Loader Contract
Every loader returns a uniform tuple:
- `X` — features + clinical covariates, samples × columns
- `y` — binary label (`sarc_status > 0`)
- `feature_groups` — `dict {name: [cols]}` of `StandardScaler`-scaled
  groups (e.g. `cont`, `clr_taxa`, `nmr`, `proteins`, `gcms`)
- `binary_cols` — covariate columns passed through unscaled

`ml_engine.build_column_transformer` turns `feature_groups` + `binary_cols`
into the preprocessing step, so adding a new assay only requires a new
loader — the engine itself never changes. `run_model_set` runs the standard
full / feature-only / clinical-only sweep per model; `run_nested_cv` is the
single-model core.

### 8.3 Shared Modelling Choices
Outer/inner 5-fold `StratifiedKFold` (seeds 222 / 111), `roc_auc` scoring,
the Dawkins-et-al. lambda path for L1 logistic regression, young controls
(`age_def < 50`) dropped, `sex` mapped to 0/1. IPTW age adjustment
(Austin & Stuart 2015) is available, with propensity fitting performed
*inside* the outer CV fold to prevent leakage. A `y_mode` parameter
(binary/continuous) supports regression diagnostics alongside the primary
classification task.

### 8.4 Per-Assay Loader Quirks
- **Metagenomics** — taxa pivoted wide; CLR transform for lasso/FC_NN,
  log-abundance for random forest (two separate loader calls).
- **Mass-spec (proteomics)** — `Sarc_`/`NoSarc_` sample-ID prefixes stripped
  to integer `record_id`.
- **NMR** — metabolite block `[5-Aminopentanoate … Valine]` minus
  `Glucose`/`Galactose`, numeric-coerced, zero-sum rows dropped, optional
  log10; threaded as a third scaled group alongside taxa.
- **LC/GC-MS** — separate DEP2 metadata file, `Unknown` diagnosis dropped,
  string `Sarc`/`NoSarc` binarized, sample IDs re-prefixed `SaMu`, feature
  names sanitized (non-word chars → `_`).

### 8.5 Running and Outputs
```bash
python run_metagenomics.py
python run_mass_spec.py
python run_nmr.py
python run_lc_gc_ms.py     # set experiment_name in config.LC_GC_MS first
```
Each writes, into that assay's `output_dir`:
`cv_results_<model>_<subset>.pkl`, `roc_curve_<model>_<subset>.pdf`, and
feature-importance CSVs. Subsets: `full`, `<feature>_only`, `clinical_only`.

Post-hoc plotting/aggregation utilities:
`plot_significance_grid.py`, `extract_fold_auc.py`,
`plot_model_performance.py`, `plot_significance_heatmap.py`,
`plot_diversity.py` — these consume the `metagenomics_R` intermediate CSVs
(`meta_filtered_*.csv`, `meta_df_FullSaMu_*.csv`) alongside the ML outputs.

### 8.6 Dependencies and Refactor Notes
`numpy`, `pandas`, `scikit-learn`, `matplotlib`, `seaborn`; `torch` +
`skorch` (FC_NN), `captum` (Integrated Gradients), `boruta` (RF selection).
The lasso and RF paths run without the deep-learning extras. The four
original per-assay scripts duplicated one engine around per-assay loaders;
they were consolidated into the shared `ml_engine`/`feature_importance`
modules with thin entry scripts. The lasso, RF, `ColumnTransformer`, and
importance-merge paths were exercised on synthetic data during the
refactor; the torch/captum/boruta paths are syntax-checked but were not
executed (those packages were unavailable in the refactor environment).
